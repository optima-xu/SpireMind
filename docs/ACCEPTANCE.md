# SpireMind v1.1 交接目标验收

日期：2026-09-28。环境：Windows、Python 3.13.13、STS2 v0.111.0、桥接 0.1.12；桥接提交和补丁见 `bridge.lock.json`。

## 当前结论

**功能与完整生命周期验收通过，高胜率验收尚未通过。** 架构、离线测试、指定模型通信、发布包隔离安装、多选恢复和回合阶段修复已有证据。EnemyKnowledge 上线后的最新实机由两个进程完成同一局：首段从主菜单到第 2 层因沙箱网络失败停止，续段稳定运行并在第 7 层死亡。知识注入已在实机出现，但该局暴露出连续低效防御和漏掉组合斩杀；本轮修复已完成固定状态与指定模型回归，尚未用新代码重跑完整实机或多 seed 胜率。

## 发现并修复的问题

1. 当前游戏版本改名的桥接 API 导致无法编译：提供固定依赖提交和兼容补丁，Release 编译完成，安装后的三个文件 hash 一致，游戏实际加载成功。
2. 静态卡牌知识未自动导入、模板数值丢失：增加版本严格校验的同步与旧缓存刷新，保留 vars/费用，避免覆盖可见手牌实时描述。
3. 非战斗卡牌选择被误当战斗选择、商店删牌价格遗漏：按公开战斗信号路由，保留选择约束与嵌套价格。
4. 多选事件反复点同一卡：实机第 12 层要求选两张，旧流程持续“选中/取消”。新增已选卡引用跟踪与循环上限；修复后自动选了两张不同卡并回到地图。测试包含真实采样响应。
5. 牌堆每种卡的数量和技能 power ID 后缀：保留 stack count，统一触发条件比对。
6. 终局证据和进度状态：保存 terminal-state，运行停止时刷新 progress 为最终结果。
7. 运行中同步 CardDB 导致旧进程拒绝新字段：这是本次验收操作引入的版本冲突，已对同步/导入增加同一 bridge 的进程互斥及回归测试。终局标记增加 full_lifecycle_complete，以区别续局终局与本进程从新局到终局。
8. 桥接 stable=true 的 None 回合阶段被误当作可行动：保留 turn_phase，并在 Adapter 等待 Play。单独统计 uncertain 回执，避免把纯粹观察到状态变化称作动作确定成功。
9. 策略忽略滑溜、误用敌方力量、在可保命时耗尽能量并留着药水死亡：加入结构化战斗核算、保命防御与药水条件；旧局面回归详情见 `DEATH_REVIEW.md`。
10. 生存搜索会重复扣除同一敌人的伤害、重复使用同一药水/卡牌目标变体：改为按物理资源分组的有界最优搜索；重复击杀、重复 Weak、未知伤害和 4,096 转移上限均有回归。
11. 模型断线可无限 fallback、pending 崩溃窗口会卡死、奖励可提前离开且药水丢弃动作过度暴露：增加连续失败熔断、prepared/dispatched 协调、奖励领取约束和药水槽条件过滤。
12. 长期流派分数受当前手牌污染、同 seed 新局继承旧记忆、升级牌收到基础事实：拆分 deck fit/scene relevance，隔离终局记忆，CardDB 按升级状态和内容摘要同步，并记录策略更新的 proposed/applied/rejected。
13. `/act` 返回状态被丢弃、每步重复 observe、trace 每条 fsync：复用 `next_decision`，去重状态记录，保留 pending journal 的强耐久并降低普通诊断 I/O。
14. 从旧终局画面启动会立即结束且留下 `run_unknown` 记忆：仅在进程首个状态允许执行绑定的 `return_to_main_menu`，生命周期动作不再读写 RunMemory；本进程自己的终局仍立即停止。
15. 模型只看到当前敌人状态，缺少怪物循环与特殊机制先验：新增固定版本 EnemyKnowledge、可重建图鉴和 `L4_enemy_knowledge`；按规范化 ID、存活状态与精确版本筛选，并把无厌沙虫的沙坑/狂乱逃离保命顺序写入高优先级提示。
16. 模型连续用低收益防御替代整回合进攻，并在 12 HP 对 32 HP 旧日雕像时漏掉 32 点组合斩杀：新增能量受限的攻击顺序搜索、Slow/易伤/格挡/多段核算、最低生存格挡与生存余量；完整证明的组合斩杀由安全层强制，非斩杀局面通过攻防事实和敌人攻略交给模型判断。

## 仍需明确的边界

这次验收只能支持其实际覆盖范围。5 角色策略包齐全不等于 5 角色稳定通关；Skill confidence 是人工规则置信度，不是测得胜率。WorkingMemory 保持短期目标并使旧动作失效；战斗仅对可证明的公开效果做有界多动作生存搜索与支持范围内的单目标攻击顺序搜索，不是完整战斗模拟器。角色专属字段（如 Osty）和桥接未导出的静态升级变体仍需扩展；act 目前由全局楼层按标准 17 层分段推导。精确卡牌数值以可见实时数据为准。

上下文 token 是估计预算；服务端 usage 才是实际计量。达到步数、token、时间限制或循环保护时属于未完成。CI 配置已提供但远端 CI 尚未执行；Python 3.11 / Linux 没有在本机验收。本目录没有远端 GitHub 发布记录。

原生与 modded 存档分离；本次实测改变了 modded 对局进度。验收前记录的两份普通存档 SHA-256 均未变化，见 `runs/vanilla-saves-check.json`。代码、配置、日志和 wheel 的凭证扫描未发现实际 API key；运行数据和交接文档原文未打入发布包。
