# Agent 架构改进：从第 31 层死亡到可审计安全层

日期：2026-09-28。依据：`runs/20260927T124201-78dab992`、`runs/20260928T012750-824f025d`、指定 DeepSeek 接口回归和本地测试。本文只说明已实现的控制边界，不把单局回放当作胜率证明。

## 复盘结论

第 31 层的真正可避免错误发生在战斗内选牌，而不是最后一个结束回合。角色只有 2 HP，敌人来伤 19；界面要求“选择 1 张牌来消耗”，候选中有两张不可打出的晕眩和一张提供 10 格挡的耸肩无视。旧 Agent 把“选择”误解成“立即打出”，消耗了耸肩无视，并在理由中声称会获得格挡和抽牌。

后续实际抽到防御+（10 格挡）与防御（7 格挡）。失去耸肩后最多只有 17 格挡，2 HP 面对 19 来伤恰好归零；若先消耗晕眩，耸肩加防御+只需 2 能量即可提供 20 格挡，能够存活。最后声称“闪电霹雳可以击杀 73 HP 敌人”是另一个算术错误，但当时已经没有生存路线。

## 已实现的控制链

```text
Bridge payload
  -> Semantic Adapter
     - 明确 selection operation
     - 保留战斗选择时的 HP/能量/格挡/来伤
  -> Deterministic Safety Kernel
     - 可见 ActionEffect
     - 按物理资源分组、能量受限且有 4,096 转移硬上限的生存组合搜索
     - verified lethal / survives / dead / unknown
  -> LLM Strategy
     - 只在安全层未决定时选择合法 action_id
  -> Validator / Execute / Verify
  -> Trace + provider diagnostics
```

### 1. 选择语义进入内部状态

Adapter 对措辞明确的战斗内消耗选择写入 `operation=exhaust` 和 `operation_effect`，将动作显示为 `Exhaust <card>`，并说明选择不会触发牌面效果。选择界面同时保留当前 HP、能量、格挡、来伤以及公开的力量状态。

安全层在这种选择中优先消耗 `Status`、`Curse` 或 `Unplayable` 卡牌。该规则覆盖本局反复发生的错误：旧模型在 10 次消耗选择中都把牌当成要使用的牌。

### 2. 生存判断采用三态

安全层输出：

- `survives`：结束回合本就能活，或存在经过核算的行动序列。
- `dead`：当前为可见致死，且所有可能改变生存结果的合法动作都已获得支持范围内的效果核算，仍无生存序列。
- `unknown`：敌方来伤或任一潜在保命动作的效果不完整。

未知能力不再被误报为“确定无解”。生命恰好降至 0 严格属于死亡。

### 3. 从一步守卫改为行动组合搜索

搜索只使用公开、可审计的当前回合效果：格挡、虚弱对当前意图的减伤、经过验证的攻击伤害、击杀攻击者后移除的来伤以及能量费用。它可以组合多张格挡，也能发现“虚弱药水 + 格挡”或“击杀一个攻击者 + 格挡”的路线。消耗品在同样能生存时排在非消耗路线之后。

这不是完整战斗模拟器。抽牌结果、回合末触发和未知能力不会被猜测；它们使结论保持 `unknown`。

### 4. 模型理由不再承担安全证明

只有 `verified_lethal=true` 的攻击才可作为确定斩杀。模型仍可给出自然语言理由，但安全层不根据理由执行动作。唯一合法且确定致死的结束回合会记录 `forced_lethal_end_turn`，从 trace 中区分“上游已经无解”和“模型主动选择致死”。

### 5. Thinking 与可复现性

当前指定配置显式关闭 `enable_thinking`，以减少每个游戏动作的延迟；`max_completion_tokens=8192` 仍作为最终 JSON 的生成上限。最近一次真实 probe 返回 `reasoning_present=false`。下方开启 thinking 的结果保留为历史接口兼容性证据。

Provider 分别统计传输失败、可重试 HTTP、输出截断和无效 JSON。每个新 run 的 manifest 保存不含密钥的模型/策略配置、Python 与包版本以及当前 Python 源码 SHA-256，使“代码随后被修改”不再破坏对局复现边界。

### 6. 防御选择采用生存阈值与整回合攻击路线

第 7 层旧日雕像实战显示，单步核算会让模型连续选择“本张牌能省 5 HP”的防御，却不比较整回合
伤害；最后还漏掉两张打击接双重打击的 32 点组合斩杀。安全层现在额外计算：

- `minimum_additional_block_to_survive`：在公开攻击意图下，保持至少 1 HP 所需的额外格挡；为 0
  时，防御不再被描述为生存必需。
- `visible_survival_margin_if_end_now`：不再出牌时结算公开攻击后的生命余量。
- `visible_max_damage_plan`：支持范围内、受当前能量约束的最佳剩余手牌攻击顺序。
- `verified_lethal_plan`：完整证明可以击杀的攻击序列；安全层逐步强制执行其首个仍合法动作。

攻击搜索模拟敌方格挡、当前易伤、攻击施加的易伤、Slow 逐张递增和多段伤害；物理卡牌不会因
目标动作变体被重复使用。它只在单个存活敌人、v0.111.x、所有可用攻击和目标能力均受支持时给出
精确结论，并受 4,096 次转移限制。非斩杀路线不会被硬编码强制，因为少掉 5 HP 与缩短战斗之间
仍需要结合牌堆、敌人增长和后续风险判断。模型目标改为最大化整局获胜机会，并要求选择非必要
格挡时给出小生存余量、完整格挡触发或无法缩短击杀回合等具体理由。

## 验证与边界

- Ruff 检查与格式检查通过。
- pytest 117 项通过，包括真实问题的消耗选择、资源/目标去重、有界生存与攻击搜索、Slow 组合斩杀、药水加格挡、0 HP 边界、未知效果三态、Provider 熔断、pending 恢复、记忆隔离和发布包回归。
- 当前模型 probe：请求与响应模型均为 `deepseek-v4-flash-0731`，`reasoning_present=false`。
- 8,192 token 历史局面回归：5 个局面，2 个实际模型决策；`model_calls=3`，其中 2 个返回 reasoning，额外 1 次为传输重试；截断 0、无效 JSON 0。
- 低效防御回归：5 个第 7 层历史状态中，4 个非斩杀状态由 thinking=false 的指定模型改选攻击
  路线，最后一个状态由安全层强制 32 点组合斩杀；4 次模型调用无传输、截断或格式错误。

仍有两个明确边界：当前 `operation=exhaust` 来自中英文明确措辞，长期应由桥接协议直接提供结构化 operation；安全搜索只覆盖已实现的公开效果，不应扩展成使用隐藏抽牌顺序或桥接动作 preview 的全知模拟器。
