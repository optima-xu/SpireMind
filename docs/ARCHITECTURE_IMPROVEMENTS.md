# Agent 架构改进：从第 31 层死亡到可审计安全层

日期：2026-09-28。依据：`runs/20260927T124201-78dab992`、`runs/20260928T012750-824f025d`、`runs/20260928T021733-8601aa9c`、指定 DeepSeek 接口历史回归和本地测试。本文只说明已实现的控制边界，不把单局回放当作胜率证明。

## 复盘结论

第 31 层的真正可避免错误发生在战斗内选牌，而不是最后一个结束回合。角色只有 2 HP，敌人来伤 19；界面要求“选择 1 张牌来消耗”，候选中有两张不可打出的晕眩和一张提供 10 格挡的耸肩无视。旧 Agent 把“选择”误解成“立即打出”，消耗了耸肩无视，并在理由中声称会获得格挡和抽牌。

后续实际抽到防御+（10 格挡）与防御（7 格挡）。失去耸肩后最多只有 17 格挡，2 HP 面对 19 来伤恰好归零；若先消耗晕眩，耸肩加防御+只需 2 能量即可提供 20 格挡，能够存活。最后声称“闪电霹雳可以击杀 73 HP 敌人”是另一个算术错误，但当时已经没有生存路线。

## 已实现的控制链

```text
Bridge payload
  -> Semantic Adapter
     - 明确 selection operation
     - 保留战斗选择时的 HP/能量/格挡/来伤
  -> Deterministic Safety Kernel
     - 可见 ActionEffect
     - 按物理资源分组、能量受限且有 4,096 转移硬上限的生存组合搜索
     - verified lethal / survives / dead / unknown
  -> LLM Strategy
     - 只在安全层未决定时选择合法 action_id
  -> Validator / Execute / Verify
  -> Trace + provider diagnostics
```

### 1. 选择语义进入内部状态

Adapter 对措辞明确的战斗内消耗选择写入 `operation=exhaust` 和 `operation_effect`，将动作显示为 `Exhaust <card>`，并说明选择不会触发牌面效果。选择界面同时保留当前 HP、能量、格挡、来伤以及公开的力量状态。

安全层在这种选择中优先消耗 `Status`、`Curse` 或 `Unplayable` 卡牌。该规则覆盖本局反复发生的错误：旧模型在 10 次消耗选择中都把牌当成要使用的牌。

### 2. 生存判断采用三态

安全层输出：

- `survives`：结束回合本就能活，或存在经过核算的行动序列。
- `dead`：当前为可见致死，且所有可能改变生存结果的合法动作都已获得支持范围内的效果核算，仍无生存序列。
- `unknown`：敌方来伤或任一潜在保命动作的效果不完整。

未知能力不再被误报为“确定无解”。生命恰好降至 0 严格属于死亡。

### 3. 从一步守卫改为行动组合搜索

搜索只使用公开、可审计的当前回合效果：格挡、虚弱对当前意图的减伤、经过验证的攻击伤害、击杀攻击者后移除的来伤以及能量费用。它可以组合多张格挡，也能发现“虚弱药水 + 格挡”或“击杀一个攻击者 + 格挡”的路线。消耗品在同样能生存时排在非消耗路线之后。

这不是完整战斗模拟器。抽牌结果、回合末触发和未知能力不会被猜测；它们使结论保持 `unknown`。

### 4. 模型理由不再承担安全证明

只有 `verified_lethal=true` 的攻击才可作为确定斩杀。模型仍可给出自然语言理由，但安全层不根据理由执行动作。唯一合法且确定致死的结束回合会记录 `forced_lethal_end_turn`，从 trace 中区分“上游已经无解”和“模型主动选择致死”。

### 5. Thinking 与可复现性

当前指定配置显式关闭 `enable_thinking`，以减少每个游戏动作的延迟；`max_completion_tokens=8192` 仍作为最终 JSON 的生成上限。最近一次真实 probe 返回 `reasoning_present=false`。下方开启 thinking 的结果保留为历史接口兼容性证据。

Provider 分别统计传输失败、可重试 HTTP、输出截断和无效 JSON。每个新 run 的 manifest 保存不含密钥的模型/策略配置、Python 与包版本以及当前 Python 源码 SHA-256，使“代码随后被修改”不再破坏对局复现边界。

### 6. 防御选择采用生存阈值与整回合攻击路线

第 7 层旧日雕像实战显示，单步核算会让模型连续选择“本张牌能省 5 HP”的防御，却不比较整回合
伤害；最后还漏掉两张打击接双重打击的 32 点组合斩杀。安全层现在额外计算：

- `minimum_additional_block_to_survive`：在公开攻击意图下，保持至少 1 HP 所需的额外格挡；为 0
  时，防御不再被描述为生存必需。
- `visible_survival_margin_if_end_now`：不再出牌时结算公开攻击后的生命余量。
- `visible_max_damage_plan`：支持范围内、受当前能量约束的最佳剩余手牌攻击顺序。
- `verified_lethal_plan`：完整证明可以击杀的攻击序列；安全层逐步强制执行其首个仍合法动作。
- `visible_setup_options`：能力牌的当回合收益与剩余触发机会，例如残酷还能强化多少次攻击。
- `visible_self_harm_options`：卖血的精确生命成本、回能、可解锁的回复/格挡后续和回合末净生命变化。

攻击搜索模拟敌方格挡、当前易伤、攻击施加的易伤、Slow 逐张递增和多段伤害；物理卡牌不会因
目标动作变体被重复使用。它只在单个存活敌人、v0.111.x、所有可用攻击和目标能力均受支持时给出
精确结论，并受 4,096 次转移限制。非斩杀路线不会被硬编码强制，因为少掉 5 HP 与缩短战斗之间
仍需要结合牌堆、敌人增长和后续风险判断。模型目标改为最大化整局获胜机会，并要求选择非必要
格挡时给出小生存余量、完整格挡触发或无法缩短击杀回合等具体理由。

工作记忆按楼层和回合维护 `lost_hp_this_turn`。每次语义核验通过的动作若使生命下降，该标记在
本回合余下决策中保持为真，用于计算恶意等依赖“本回合失去生命”的条件效果；进入下一回合或
楼层时自动清零。

## 验证与边界

- Ruff 检查与格式检查通过。
- 全量 pytest 通过，覆盖真实问题的消耗选择、资源/目标去重、有界生存与攻击搜索、卖血回能、能力牌触发、同回合生命损失记忆、Slow 组合斩杀、药水加格挡、0 HP 边界、未知效果三态、Provider 熔断、pending 恢复、记忆隔离、计算器工具往返和路线展望。
- 当前模型 probe：请求与响应模型均为 `deepseek-v4-flash-0731`，`reasoning_present=false`。
- 8,192 token 历史局面回归：5 个局面，2 个实际模型决策；`model_calls=3`，其中 2 个返回 reasoning，额外 1 次为传输重试；截断 0、无效 JSON 0。
- 低效防御回归：5 个第 7 层历史状态中，4 个非斩杀状态由 thinking=false 的指定模型改选攻击
  路线，最后一个状态由安全层强制 32 点组合斩杀；4 次模型调用无传输、截断或格式错误。

仍有两个明确边界：当前 `operation=exhaust` 来自中英文明确措辞，长期应由桥接协议直接提供结构化 operation；安全搜索只覆盖已实现的公开效果，不应扩展成使用隐藏抽牌顺序或桥接动作 preview 的全知模拟器。

## 第 17 层 Boss 死亡复盘后的补强

`runs/20260928T021733-8601aa9c` 的仪式兽战斗揭示三个独立问题：第 7 回合敌人 170 HP，公开的 Plow 能力写明降至 150 HP 会眩晕，但旧决策在手中有 23 伤完美打击时仍选择防御；第 9 回合 Ringing 限制每回合只能打 1 张牌，攻击搜索却给出多张牌方案；长期计划还错误宣称突破和熔融之拳可以积累力量。

现在，v0.111.x 的安全层只在公开 Plow 描述和阈值可核实时将触发眩晕视为取消敌方当回合攻击，并在可见致死时优先执行该动作。攻击与生存搜索均遵守 Ringing 的剩余出牌上限；若能力描述或牌面效果无法核实，搜索保持未知。Boss 开局受伤且战斗仍长时，可提早使用有持续收益的明晰提取物或敏捷药水。运行策略读取同版本牌库中的已有牌事实；保存或加载 Boss 计划时会拒绝明确声称从不产力量的具名卡牌获得力量的说法。

在原始状态离线重放中，第 7 回合会选择触发眩晕的 23 伤完美打击，核算取消 28 点来伤；第 9 回合攻击规划从三张牌收敛为合法的一张牌。新增回归覆盖这些边界和药水时机；本次没有再次请求模型或完成新一局真实游戏，不能据此声称胜率已经提升。

## 状态与资源核算审计

对 `runs/20260928T093955-4633813e/bridge-observations.jsonl` 的 254 个战斗快照离线归一化并执行核算后，确认桥接实际提供了手牌的 `affliction_id`、`affliction_amount`、`target_dynamic_vars`、`unplayable_reason`，以及敌方意图的 `total_damage`。其中活力火花使技能牌附着污染 2；`PRODUCTION` 本身只给能量，只有附着污染时才加污染。旧核算未利用这些字段，可能低估新污染后的来伤或把当前污染重复计入。现在只对新获得的污染按仍存活敌人的攻击段数加算，段数缺失时停止精确预测；当前污染已在桥接意图中，不重复加算。脆弱造成的小数格挡按实际显示取整，当前巨人化只用于下一张攻击，目标专属数值进入手牌上下文并用于核对攻击和格挡。

搜索现在按行动顺序处理能量、卖血、治疗和生命上限；只有桥接明确标记 `not_enough_energy` 的牌才可作为回能后的后续牌。单张攻击都未击杀、但多张攻击可合计击杀时，完整攻击搜索可证明生存，不再误报“无解”。搜索触及转移上限、自伤先致死、未知当前能力、升级/随机消耗手牌、下一张攻击复制、反伤等未实现效果时，不生成精确斩杀或生存证明。`NO_DRAW_POWER` 会抑制本回合即时抽牌，能力牌上的抽牌数不再误写成打出时立刻抽牌。

本次验证为全量 pytest、Ruff 检查与格式检查通过，254 个实机快照回放无解析或核算异常；未让修改后的版本重新打完一局，因此不据此推断胜率。

## 算术工具与早期路线、资源决策

`runs/20260928T035722-9118b264` 的第 154 次决策在 37/80 HP、`elite_readiness=0.306`
时选了精英；实际上普通怪分支也能到同一商店、休息点和 Boss。第 182 次决策在 9/80 HP、
304 金的商店选择离开，理由是留钱给以后的改进，但可见地图上此店后只有休息点和 Boss。
第 207 次战斗决策又把对 48 HP 随从的 11 点打击描述成击杀。

模型现在通过 OpenAI-compatible `tools` 调用本地 `calculate`。`required` 模式要求每次模型决策
至少有一次成功计算，最多四轮、每轮八次工具调用；表达式只允许有限的算术、`min/max/abs`
及数值比较，禁止代码执行。调用表达式与结果写入决策 trace；API key 不会进入请求正文或日志。
指定 DeepSeek 部署的实测工具往返正确算出 `48-11=37`，模型名匹配，thinking 关闭。
该部署在工具返回后偶尔忽略 JSON mode、给 JSON 加说明文字；Provider 只提取可解析的单个
JSON 对象，再用严格 schema 和合法 `action_id` 检验。

地图阶段额外生成每个可选节点的可见路径摘要：精英/普通怪/商店/休息点的最小与最大次数、
Boss 楼层、共享后续节点、精英最少的路径。所选路线的展望由代码计算并持久化到 RunMemory，
在商店读出、跨幕清除。低血量且准备度低时，若普通怪和精英分支的后续节点完全相同，
规则选择普通怪。若低血量商店是 Boss 前最后一家已知商店，规则只先打开货架检查可负担的
选项，随后仍允许不买。不会把“购物可选”误读为“总该为不存在的下家商店留钱”。

增加一个独立 LLM 路线/资源复核子代理不是当前第一步：同一份缺失未来路线的输入即使调用
两次模型也无法形成可靠比较，且强制计算器已增加请求量。若后续对照多局仍发现高风险
路线或临 Boss 购物错误，可以在地图分叉、最后商店与休息点加只读的结构化复核器：它只
评估同一状态快照上的各合法选项、给出不确定性，由主代理核对 `decision_id` 后决定；
不让复核器直接操作游戏或改写记忆。

算术工具能修正运算，不保证模型选对公式或目标。对保存的第 207 次局面做离线模型调用时，
模型虽使用了工具，仍需依赖可见机制提示来理解首领与随从关系。因此 v0.111.x 的
`minion_power` 依据本地敌人资料被纳入不改变受击伤害的已知能力；同一局面重新核算，
三次 11 点打击对 48、37、173 HP 目标的 `verified_lethal` 均为 `false`。加入
`target_hp_after` 后再离线请求一次指定模型，它调用计算器算出 `37-11=26`，选择攻击
37 HP 随从且没有再声称击杀；这是单个历史状态的决策回归，不是实机胜率证据。
